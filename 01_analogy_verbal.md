# Analogy (Verbal)
> The art of structural equivalence: decoding relationships, not memorizing pairs. The exam doesn't test your vocabulary; it tests your ability to map structural logic from one domain to another.

## Chapter 1: The Core Framework of Analogical Reasoning

### Section 1 | What Is an Analogy? The Logical Skeleton

Every analogy is a statement of *relationship equivalence*. When the exam presents `A : B :: C : D`, it demands: *"The relationship between A and B is exactly the same as the relationship between C and D."* The colon (`:`) means "is related to," and the double colon (`::`) means "in the same way as."

The cognitive trap is that most students read the pair and immediately search for *any* relationship. This is disastrous. The correct approach is to generate a *precise, multi-condition relationship statement* that is so specific that it uniquely identifies the correct option. For example, if you see `Doctor : Hospital`, the relationship is not merely "works in." It is *"a professional who practices their primary vocation in a specialized institution designed for that vocation, and is legally required to be present for its core function."* That specificity filters out distractors like `Teacher : School` (works in) but also `Surgeon : Operating Theatre` (too narrow).

**The golden rule**: Define the relationship in two sentences. The first sentence states the primary action/connection. The second states the *exception* or *qualifier*. If the second sentence can be violated by an option, that option is dead.

### Section 2 | The Set Theory of Analogy Types

All verbal analogies collapse into five fundamental relationship classes. Memorize this taxonomy not as a list, but as a diagnostic flowchart:

| Relationship Class | Core Logical Engine | Common Exam Subtypes |
| :--- | :--- | :--- |
| **Class Inclusion** | One term is a subset, member, or instance of the other. | Member-Group (e.g., `Fish : Shoal`); Part-Whole (e.g., `Keyboard : Computer`); Genus-Species (e.g., `Mammal : Whale`). |
| **Functional Dependency** | One term exists to serve, enable, or constrain the other. | Worker-Tool (`Carpenter : Saw`); Object-Function (`Pen : Write`); Action-Result (`Exercise : Fitness`). |
| **Causal or Sequential Logic** | One term precedes, causes, or is a prerequisite for the other. | Cause-Effect (`Cloudburst : Flood`); Stage-Process (`Chrysalis : Butterfly`); Means-End (`Study : Exam`). |
| **Attribute Mapping** | One term possesses a specific, measurable, or qualitative property. | Quality-Degree (`Warm : Hot`); Material-Object (`Cotton : Fabric`); Measurement-Unit (`Length : Meter`). |
| **Association & Symbolism** | The connection is non-physical, cultural, or contextual. | Symbol-Entity (`Dove : Peace`); Source-Product (`Milk : Cheese`); Place-Event (`Eden : Serpent`). |

[alert type="warning"]
**Critical Cognitive Bias:** The *Availability Heuristic* will make you latch onto the first relationship that "feels right." A question like `Pencil : Eraser` could be "used together" or "one corrects the other's mistake." The exam will provide options that satisfy the *weaker* relationship. You must always choose the *strongest, most constrained* relationship. If two options fit your primary relationship, you haven't defined it tightly enough. Go back to the stem and look for a secondary filter.
[/alert]

## Chapter 2: Letter-Based Analogy

### Section 1 | The Alphabet as a Number Line

The English alphabet is a sequence of 26 positions. The core assumption is that each letter is an integer between 1 and 26. All letter-based analogies are hidden arithmetic or positional logic. You cannot solve these visually; you must convert every letter to its numerical index instantly. This is not optional.

Two types of positional logic dominate:
1.  **Direct Indexing**: `A=1, B=2, ... Z=26`.
2.  **Reverse Indexing**: `A=26, B=25, ... Z=1`. This is often used as a distractor layer.

[alert type="success"]
**The EJOTY Anchor**: Memorize these five positions as absolute anchors:
E = 5, J = 10, O = 15, T = 20, Y = 25.
This allows you to mentally calculate any letter's position in less than a second via addition/subtraction from these anchors. For example, `P` is `O+1 = 15+1=16`. `M` is `O-2 = 15-2=13`.
[/alert]

### Section 2 | Decoding the Patterns

The relationship in letter analogies is almost always a composite operation involving addition, subtraction, multiplication, division, or reverse-order operations. The pattern must be applied *consistently* to the first pair to derive the second.

**Pattern 1: Arithmetic Progression (Linear Shift).**
`C : E :: F : ?` → `C(+2) = E`. Therefore, `F(+2) = H`. Simple, but the trap is the shift value. The shift could be `+3, -4, +5, -1`, or even alternating (`+2, -3, +2`). Always compute the *net shift* from the first letter to the second.

**Pattern 2: Sum of Positions.**
`AB : C :: DE : ?` → `A(1)+B(2) = 3 = C`. Therefore, `D(4)+E(5) = 9 = I`.
The trap here is when the sum exceeds 26. You must then apply modular arithmetic (wrapping around) or digit-sum reduction, depending on the question's pattern.

**Pattern 3: Difference of Positions.**
`C : G :: F : ?` → `G(7) - C(3) = 4`. But what is the relationship? The second is the first *plus 4*. Apply `F(6)+4 = J(10)`. However, the relationship could be "Absolute difference" or "Second - First = constant".

**Pattern 4: Reverse Alphabet and Positional Complements.**
`A : Z :: B : ?` → A is the reverse complement of Z (`A+Z = 27`). Therefore, `B+Y = 27`, so `B : Y`. This is a favorite for creating impossible-looking questions.

[flashcards title="Letter Analogy Mastery"]
| Operation | Symbolic Form | Example |
| :--- | :--- | :--- |
| Forward Shift | `L1 + n = L2` | `K : M` (+2) |
| Backward Shift | `L1 - n = L2` | `N : L` (-2) |
| Sum to Letter | `Pos(L1) + Pos(L2) = Pos(L3)` | `A : B :: C` (1+2=3) |
| Difference to Letter | `\|Pos(L1) - Pos(L2)\| = Pos(L3)` | `E : A :: D` (5-1=4) |
| Reverse Complement | `Pos(L1) + Pos(L2) = 27` | `R : I` (18+9=27) |
| Alternating Shift | `+a, -b, +a, -b...` | `A : C :: E : D` (+2, -1) |
[/flashcards]

[example]
**Question:** `AC : EG :: ? : MO`
**Solution:**
Step 1: Convert to positions. `AC` = 1, 3. `EG` = 5, 7.
Step 2: Find the pattern. `1 → 5` (+4), `3 → 7` (+4). So, the operation is `+4` applied to each letter.
Step 3: Apply `+4` to `MO`. `M(13) + 4 = 17 (Q)`, `O(15) + 4 = 19 (S)`.
Step 4: The answer is `QS`.
**Final Answer:** `QS`
[/example]

## Chapter 3: Number-Based Analogy

### Section 1 | The Prime Directive of Numbers

Numbers are relationships incarnate. Unlike letters, numbers have infinite properties: primality, squares, cubes, factors, multiples, digit sums, reversing digits, and the basic operations. The key is to *force* the stem pair into the simplest possible mathematical expression.

**The Cognitive Rule**: Always check for the *binary* operation first. Is the second number the result of performing one arithmetic operation on the first? If not, check for *composite* operations (e.g., `(x * 3) + 2`). If not, check for *digit-wise* operations (e.g., square of first digit + cube of second digit).

### Section 2 | Hierarchical Pattern Detection

When you see `A : B`, treat `A` as the input and `B` as the output. Generate a *function* `f(A) = B`. Then apply `f(C)` to get `D`. If the function is not apparent, test these in descending order of probability:

1.  **Direct Arithmetic**: `B = A + n`, `B = A - n`, `B = A × n`, `B = A ÷ n`. This is the most common. The trap is the sign change; sometimes the relationship is `A - n = B` for the first pair and `C - n = D` for the second.
2.  **Two-Step Operations**: `B = (A × p) ± q`. Here, the multiplier and the addend are often the same across the pair. For example, `3 : 11` (×3 + 2), `7 : 23` (×3 + 2).
3.  **Power Functions**: `B = A²`, `B = A³`, or `B = A² ± A`. Example: `2 : 4` (square), `3 : 9` (square), but then `4 : 16` vs `4 : 20` (square + 4). The pattern is defined by the *operation*.
4.  **Digit Manipulation**: `A = 12, B = 3` (1+2), `A = 24, B = 8` (2×4), `A = 36, B = 18` (3×6). The relationship is between the *digits* of `A`.
5.  **Square/Cube of Digit Sum**: `A = 23, B = 25` ( (2+3)² = 25 ).
6.  **Reverse of the Number**: `A = 12, B = 21` (reverse). Or `A = 12, B = 3` (12 ÷ 4 = 3, where 4 is the number of letters in "twelve"? No, that's a trap. Stick to math).

[alert type="danger"]
**The Prime Trap**: Many aspirants over-apply prime number logic. If you see `16 : 31`, a weak answer is "prime numbers" because 31 is prime. But the stronger relationship is `(16 × 2) - 1 = 31`. Always prefer *operational* logic over *property* logic (e.g., prime, even, odd) because operations generate specific, testable outputs for the second term.
[/alert]

[example]
**Question:** `64 : 100 :: 144 : ?`
**Solution:**
Step 1: Recognize perfect squares. 64 = 8², 100 = 10². The relationship is 8→10. The operation is `+2`. So `√64 = 8`, `8+2 = 10`, `10² = 100`.
Step 2: Apply to 144. `√144 = 12`, `12+2 = 14`, `14² = 196`.
**Final Answer:** 196
[/example]

## Chapter 4: Word-Based Analogy

### Section 1 | Beyond Synonyms and Antonyms

Word analogies are the most cognitively complex because they involve meaning, context, and connotation. The exam is not testing your vocabulary; it is testing your ability to *abstract the relationship* from words you may not know. The logic is always structural, not lexical.

**The Five Dominant Word-Relationships**:

1.  **Class/Instance**: `Eagle : Bird`. The first is a specific member of the second. The trap is `Sparrow : Bird` – it also fits, but the question will have only one answer. Use the *degree of specificity* as a filter.
2.  **Part/Whole**: `Electron : Atom`. The first is a constituent part of the second. The trap is `Cell : Organism` (also a part/whole, but the scale is different). The exam expects you to recognize the *hierarchical level* of the part.
3.  **Action/Object**: `Paint : Canvas`. The first is an action performed on the second. `Sculpt : Clay` fits, but `Write : Pen` is action/instrument, not action/object.
4.  **Place/Person**: `Classroom : Teacher`. The first is the location, the second is the primary agent in that location. `Courtroom : Judge` fits, but `Kitchen : Chef` also fits. The filter is the *mandatory presence* for the core function.
5.  **Cause/Effect**: `Drought : Famine`. The first is a primary cause of the second. `Flood : Destruction` fits.

### Section 2 | The Semantic Constraint Strategy

To avoid getting lost in ambiguity, use the *Constraint Pairing* method:
1.  Write the relationship as a full sentence. "A is used by a B to accomplish a specific task."
2.  Test the sentence on the options. If it fits, keep it.
3.  Now, add a *condition* to the sentence that is true for the stem but eliminates at least one option. "A is used by a B to accomplish a specific task *that requires specialized skill*." This eliminates `Student : Computer`.

[flashcards title="Word Analogy Relationship Matrix"]
| Relationship | Question Stem Example | Distractor Trap |
| :--- | :--- | :--- |
| Member-Group | `Bird : Flock` | Confusing with "Collection of..." |
| Worker-Tool | `Carpenter : Chisel` | Confusing with "Worker-Workplace" |
| Product-Resource | `Paper : Wood` | Confusing with "Product-Factory" |
| Gender-Male/Female | `Horse : Mare` | Confusing with "Young-One" |
| Degree-Intensity | `Enrage : Annoy` | Confusing synonyms of the same degree |
[/flashcards]

[example]
**Question:** `Mendicant : Beggar :: ? : ?`
**Solution:**
Step 1: Recognize the relationship. A "mendicant" is a formal/theological term for a beggar. They are exact synonyms, but one is more elevated or formal.
Step 2: Find a pair with a similar formal/informal or semantic elevation. `Scholar : Student` (scholar is a formal term for an advanced student, not a synonym). `Monarch : King` (monarch is formal, king is concrete; they are synonyms with a similar register). This is the best fit.
**Final Answer:** `Monarch : King`
[/example]

## Chapter 5: GK/General Knowledge-Based Analogy

### Section 1 | The Assumption of Common Knowledge

These analogies are not random trivia. They draw from *universal competitive-exam common ground*: capitals of major countries, currencies of key economies, major religions and their founders, primary national symbols, scientific discoveries, and historical capital-city associations. The underlying logic is *conventional association*.

**The Framework**:
- **Country-Capital**: `India : New Delhi`. The relationship is "Country and its administrative capital." The trap is `India : Mumbai` (financial capital) – a classic distractor.
- **Author-Book**: `Shakespeare : Hamlet`. The relationship is "Author and a seminal work." The trap is `Shakespeare : Sonnet 18` (also valid, but less representative).
- **Scientific Discovery/Inventor**: `Penicillin : Fleming`. The relationship is "Discovery and its discoverer."
- **Symbol/National Emblem**: `Kangaroo : Australia`. The relationship is "Symbol and Country."

### Section 2 | The Precision Filter

The key to GK analogies is *specificity of association*. If the question is `Gandhi : Sabarmati Ashram :: ? : ?`, the relationship is "Leader and their primary residence/headquarters." The trap is `Gandhi : Dandi` (site of a march, not a residence). You must know the *exact* nature of the relationship in the stem.

[alert type="info"]
**Exam Hack**: In 90% of GK analogies, the relationship is one of these three: 1) Country-Capital, 2) Author-Book, 3) Scientist-Invention. If a question seems obscure, it is almost certainly one of these three categories. If you don't know the exact answer, use the relationship category to eliminate options that violate the category.
[/alert]

## Chapter 6: Mixed (Letter + Number) Analogy

### Section 1 | The Hybrid Logic Engine

This is the most challenging category because it forces you to switch cognitive tracks between alphabetic and numeric reasoning. The core principle is: *letters encode numbers, and numbers encode letters, but the relationship is always mathematical*.

**Pattern 1: Letter Position + Number = Letter Position.**
`A : 1 :: C : ?` → A is the 1st letter. C is the 3rd letter. The relationship is "Position = Number." So C : 3.
**Pattern 2: Number + Letter = New Letter (using positional addition/subtraction).**
`B : 3 :: E : ?` → B=2. 2+? = 3 → `? = 1`. So E(5) + 1 = 6 = F. The answer is F.
**Pattern 3: Letter Pair + Number Pair.**
`AD : 14 :: BE : ?` → A=1, D=4, sum = 5. Wait, the question says 14. That means the relationship is not sum, but concatenation. 1 and 4 are written as "14". So A(1) and D(4) become 14. Therefore, B(2) and E(5) become 25.
**Pattern 4: Number to Letter to Number.**
`23 : C :: 11 : ?` → 23 is not directly C. But 2+3=5 = E. Or 23 is a prime number, and C is the 3rd letter... This is a dead end. The correct pattern is often the *sum of digits* or *difference of digits* to get a letter.

### Section 2 | The Cross-Domain Translation Rule

Always convert mixed analogies to a *single domain* before solving. If you see a number, ask: "Is this a position index? A sum? A difference? A product?" If you see a letter, ask: "Is its position the base number?"

[example]
**Question:** `B 2 : D 4 :: ? : ?`
**Solution:**
Step 1: Observe the pattern. B is the 2nd letter, D is the 4th letter.
Step 2: The relationship is `Position of First Letter = Second Number`.
Step 3: So the first term is a letter, the second term is its position. The second term is a letter, the fourth term is its position.
Step 4: The answer must follow `X : Pos(X) :: Y : Pos(Y)`. So `F : 6 :: H : 8` is a valid answer.
**Final Answer:** `F : 6 :: H : 8`
[/example]

[alert type="success"]
**The Ultimate Shortcut**: For any mixed analogy, write down the alphabet positions of the letters immediately. Then, treat the entire analogy as a pure number analogy. For example, `AB : 8` becomes `(1+2)+5 = 8` or `(1×2)+6 = 8`. The number 8 is just a result. Don't get intimidated by the mix; it's just arithmetic with a translation step.
[/alert]
